Three principles

In law, an invented answer costs more than no answer.

A wrong deadline loses an appeal; a wrong amount ends up in court filings. The whole product is built around that asymmetry.

01

Code computes, the model writes

Timelines, deadlines, priorities, linking a letter to its matter: all derived from the database by rules. The model interprets a request and puts a result into words. A date read from a table cannot be invented.

02

Nothing is shown unverified

Cited sources must exist, every figure must appear in the document, the quoted sentence must be found in it, and the source must really say what is claimed. If any check fails, JurisMind declines, and says so as a result.

03

The database enforces access

Isolation relies on PostgreSQL Row-Level Security: every query runs under the lawyer's identity. Two lawyers open the same page and see 43 and 26 matters, none in common. A badly written endpoint cannot leak anything.

How it works

From archives nobody reads to a matter you can question.

  1. Connectors to existing systems.

    The practice database and the CRM are read through an anti-corruption layer: duplicates merged with care, "MISC" categories reclassified, nothing overwritten.

  2. Document reading.

    PDF, Word and scans run through French OCR, split along legal structure (articles, operative part) rather than by character count.

  3. Hybrid search.

    Meaning (pgvector), keywords (French full-text) and exact references such as "FA-2025-978", fused by RRF, only within the matters the database lets you see.

  4. Verified answer.

    The model answers in JSON with its sources and a quote; five checks written in code decide whether the answer is shown.

  5. Agents under approval.

    Matter assistant, client intelligence, document analysis, mail triage. They propose; a lawyer approves, and only the approval has an effect, all the way into the CRM.

In the demo

What you can try.

  • Sign in as two different lawyers, and see that they do not see the same matters.
  • Ask the prepared questions: invoice amounts, formal notice deadlines, notice periods, and questions with no answer.
  • Open a matter: parties, team, running deadlines, instant timeline.
  • Check the firm's deadlines, recomputed from the deeds.
  • Have a scanned document analyzed, and read what OCR got out of it.
  • Approve or reject the mail agent's proposals.
  • Run a conflict check before taking on a new client.
Known limits

What it does not do.

  • It sends no email: an approved draft is "approved for sending", a human sends it.
  • On CPU an answer takes 20 to 100 seconds; with an OpenAI key, a few seconds.
  • The conflict check compares names: it cannot see a renamed company or a subsidiary.
  • In this online demo, only the prepared requests get a model answer.
